## 8. 診断ログ取得指示

現時点で必要な実機ログは、共通ジェスチャー基盤の移行前基準として次の2件とする。見た目は実画面で別途確認する。

### ログA：ストレッチの完成済み並べ替え基準

- 開始：診断RECを開始してストレッチへ移動
- 操作：種目またはルーティンを長押しし、別のカードの前後へ移動する
- 続けて：指を画面下端へ移動し、自動スクロールが始まるところまで操作する
- 停止：固定停止ボタンで終了
- 補足メモ：`再統合前基準・ストレッチ並べ替えと自動スクロール`

### ログB：タスクで現在失敗している操作

- 開始：診断RECを開始してタスクへ移動
- 操作：ドラッグハンドルを長押しし、今日使うタスク枠へ移動して離す
- 続けて：もう一度タスクを長押しし、指を画面下端へ移動する
- 停止：固定停止ボタンで終了
- 補足メモ：`再統合前不具合・今日使う枠への追加と自動スクロール`

2件をDropboxへまとめて送信した後、ログを比較して共通基盤の入力方式を確定する。

- タスク固有処理：「今日使うタスク」を共通コントローラーの追加ドロップ先として登録

- ナビ：各モードの状態更新を共通管理へ委譲し、`aria-current` を付与
- 固定UI：一時停止、ナビ、診断停止の実測高さから共通スタックを計算
- 保存・同期：メニュー、FOCUS、タスク、今日の予定、レシピ、画像参照をデータ提供者登録APIへ移行。多重ラッパーを解消し、既存データ形式は維持
- 画面遷移：タスク、レシピ、診断の戻る分岐を優先度付き共通ルーターへ移行
- ヘッダー：ナビバーと重複していたホーム画面の設定ボタンを削除
- 共通ヘッダー：ストレッチ、タスク、レシピ、設定を並列トップページとして登録。戻るを隠し、ページ名・バージョン・更新を共通表示
- ヘッダー競合除去：遅延実行される旧処理から、バージョン・更新ボタンの表示制御を撤去
- トップ階層履歴：4画面間の移動は履歴の深さを増やさず、右スワイプでストレッチへ戻る親子関係を解消
- トップ階層保護：Androidの戻るジェスチャーではトップ画面からアプリ外へ移動せず、その場に留まる
- 履歴互換：更新前の履歴が残っていても、現在の表示画面を基準にトップ階層の戻るジェスチャーを遮断
- APK戻る経路：ブラウザ履歴だけでなく、APKから直接呼ばれる共通戻る処理の入口でもトップ階層を遮断
- レシピ追加：トップヘッダーの「＋」を本文上部へ移動
- セクション操作：ストレッチとレシピの追加ボタンを共通サイズ・配置へ統一
- 配列並べ替え：ストレッチ、タスク、レシピの実データ移動も共通関数へ統一。レシピの古いorder値による巻き戻しを解消
- 旧基本並べ替え：`index.html` の旧タッチ・HTML5ドラッグ処理を削除し、共通コントローラーだけに統一
- 自動検証：`node scripts/verify-reintegration.mjs` を追加
- 画面ライフサイクル：カード装飾、タイマーテーマ、履歴グラフ、記録ヘッダー、更新ボタン、一時停止ドック、タイマー状態、PiPの10個の多重showラッパーを登録方式へ移行

- 画面離脱：種目編集の未保存確認を、遷移中止可能な共通beforeフックへ移行
- 戻る処理：タイマー終了確認、タイマー予備経路、種目編集の3つを優先度付き共通ルーターへ移行

## 10. v0.13.0公開前の実機確認

1. タスクカードを左・右へスワイプし、削除・複製が同じ角丸で表示される
2. レシピカードを左・右へスワイプし、削除・複製が表示され実行できる
3. ストレッチの種目を長押しし、上下端で自動スクロールし、挿入ライン位置へ並べ替えられる
4. タスクのハンドルを長押しし、上下端で自動スクロールする
5. タスクを「今日使うタスク」へ追加し、長押しで戻せる
6. 診断記録中に全モードを移動し、停止ボタンがナビや一時停止UIと重ならない

上記以外の保存、同期、タイマー、画像、レシピ入力、診断メモは既存形式・既存所有者を変更していない。
